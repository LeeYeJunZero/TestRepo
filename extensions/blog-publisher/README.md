# 블로그 포스팅 스튜디오 1.3.4

네이버 블로그용 Chrome Manifest V3 확장 프로그램입니다. 별도 서버나 Node 설치 없이 확장 프로그램 폴더를 불러와 사용합니다. API 키와 네이버 로그인은 사용자가 직접 설정합니다.

## 설치

1. 배포 ZIP을 압축 해제합니다. `manifest.json`이 들어 있는 `blog-publisher` 폴더를 확인합니다.
2. Chrome 주소창에 `chrome://extensions`를 입력합니다.
3. 오른쪽 위 **개발자 모드**를 켜고 **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. `manifest.json`이 들어 있는 폴더를 선택합니다.
5. 퍼즐 아이콘에서 **블로그 포스팅 스튜디오**를 고정합니다. 아이콘 또는 `Alt+Shift+B`로 전체 화면 대시보드를 엽니다.
6. 업데이트는 같은 폴더의 파일을 교체한 뒤 확장 프로그램 관리 화면에서 새로고침합니다. 자동 원격 업데이트 기능은 없습니다.

업데이트 후에는 기존 대시보드 탭을 닫고 확장 아이콘으로 다시 여세요. 화면과 백그라운드 버전이 다르면 작업을 보내지 않고 버전 불일치를 안내합니다. 키 적용 시 연결 끊김·백그라운드 무응답·API 요청 오류를 구분해 표시하며, 통신 실패한 작업을 임의로 다시 전송하지 않습니다. 오류의 코드 위치만으로 API 키 자체의 유효성은 판단할 수 없습니다.

v1.3.2부터 화면 HTML의 필수 요소·버전도 초기화 전에 확인합니다. 예전 HTML과 새 스크립트가 섞이거나 실행 중 요소가 사라지면 `hidden`/`textContent`의 null 예외를 반복하지 않고 화면의 추가 요청을 중단합니다. 복구 안내의 **현재 입력 백업 받기**로 미저장 텍스트를 보관할 수 있습니다. 이 복구 파일은 정식 이미지 포함 백업을 대체하지 않으며, 기존 Chrome 저장소의 원고·이미지·키를 삭제하지 않습니다.

## API와 모델

- 지원: OpenAI Responses API, Anthropic Messages API, Google Gemini generateContent API.
- 제공자를 고른 뒤 해당 제공자의 **API 키**를 입력하고 **적용**합니다. ChatGPT/Claude/Gemini 웹 구독과 API 사용료는 별개입니다.
- 적용한 키로 서버의 모델 목록을 조회합니다. 모델을 선택하면 모델 ID가 입력됩니다. 직접 입력도 가능합니다.
- OpenAI 목록에서는 이미지·음성·임베딩 전용 모델을 이름 기준으로 제외합니다. 모델 목록에 있어도 Responses 텍스트 생성 권한·잔액·모델 제한에 따라 생성은 실패할 수 있습니다. Gemini는 generateContent 지원 모델만 표시합니다.
- Anthropic 조직의 브라우저 요청 제한으로 키가 유효해도 거부될 수 있습니다. 이 경우 해당 계정 정책에 맞는 서버 프록시가 필요하며 본 버전에는 포함하지 않습니다.
- 키는 기본으로 Chrome 세션에만 보관합니다. 종료 후에는 다시 입력해야 하므로 재시작 이후 AI 생성 예약에는 키 재입력이 필요할 수 있습니다. 원고를 미리 생성해 예약하면 실행 시 API 키가 필요 없습니다.
- **이 기기에 키 보관**은 확장 프로그램 로컬 저장입니다. 암호화 금고가 아니며 기기 계정에 접근 가능한 사람에게서 키를 보호하지 않습니다. 브라우저 동기화, 로그, 원고 백업에는 키를 넣지 않습니다.
- 본인이 작성한 키워드·주제·페르소나·참고자료·추가 요구사항은 선택한 API 제공자에게 글 생성 요청으로 전달됩니다. 별도 검색·웹페이지 수집·AI 이미지 생성은 하지 않습니다.

## 글 작성

1. 키워드, 주제, 페르소나를 입력합니다. 독자·문체·길이·참고자료도 지정할 수 있습니다.
2. 제목을 직접 정했다면 **제목**에 먼저 입력합니다. **글 작성 + 제목 기준 검수**를 누르면 제목을 고정해 초안을 작성하고, 같은 API·모델로 별도의 페르소나 검수 요청을 보내 본문을 교정합니다. 제목을 비워두면 초안의 생성 제목을 검수 기준으로 사용합니다.
3. 제목·본문·태그를 직접 수정하고 미리보기를 확인합니다. 작성·검수 중 입력을 수정한 경우 AI 결과는 임시저장 목록으로 보내며 현재 편집 내용을 덮어쓰지 않습니다.
4. 페르소나는 말투·관점입니다. 실제 없는 경력·성과·후기·학교별 특성을 만들지 않도록 요청하며, 사실 확인은 별도로 필요합니다.
5. 태그는 본문 마지막에 해시태그로 추가합니다. 네이버 태그 설정 항목을 조작하는 기능은 없습니다. 본문은 일반 텍스트 중심이며 동영상·표·서식 자동 삽입은 지원하지 않습니다.

## 제목 기준 페르소나 검수·교정

제목이 **짜장면 레시피**인데 본문은 **짜파게티 조리법**이면 제목이 약속한 내용과 다릅니다. 검수 단계는 본문에 맞춰 제목을 바꾸는 대신, 제목을 기준으로 대상·범위·글 유형·독자 기대를 확인하고 페르소나의 말투를 유지하며 본문을 고칩니다.

- **자동 작성:** 초안 작성 API 1회 → 제목 기준 검수·교정 API 1회. 보통 최소 2회의 API 사용료가 발생합니다. 재시도나 재검수는 추가 호출입니다.
- **직접 쓴 글:** 제목·본문·페르소나·API 모델을 입력하고 **제목 기준 검수·교정**을 누릅니다. 키워드·주제는 참고하되 기준 제목과 충돌하면 제목을 우선합니다.
- **검수 결과:** 검수 통과 / 교정 후 통과 / 검수 미통과, 요약, 문제와 수정 이유, 검수 전 원고를 확인합니다. 상세 로그에도 시작·통과·교정·중단과 이유를 남깁니다.
- **원문 보관:** 검수 요청 전에 원고를 로컬 임시저장합니다. 검수가 실패해도 초안을 잃지 않으며, 작성 중 직접 수정한 글을 늦게 도착한 결과로 덮어쓰지 않습니다.
- **제목 고정:** 검수 응답이 제목을 변경하거나 최종 내용이 제목·범위·페르소나 기준을 통과하지 못했다고 답하면 결과를 거부합니다.
- **이미지 위치 보존:** 본문의 `[[1]]` 같은 삽입 표시가 누락·추가되거나 순서가 바뀌면 교정 결과를 사용하지 않습니다. 이미지 파일은 검수 API에 보내지 않습니다.
- **실행 전 검사:** 네이버 편집기 채우기·임시저장·발행은 현재 원고의 검수 통과를 확인한 뒤 시작합니다. 검수 실패·API 오류·키 미설정 시 검수를 건너뛰어 보내지 않습니다.
- **재검수:** 제목·본문·태그·페르소나·키워드·주제·독자·문체·참고자료·요구사항·API 모델·이미지 위치가 바뀌면 검수 결과가 만료됩니다. 내용이 같고 실행 방식이나 블로그 ID만 바뀌면 통과 결과를 재사용합니다. 가져온 백업 원고는 다시 검수합니다.
- **예약:** 미리 검수한 원고는 등록한 복사본과 일치할 때 결과를 재사용합니다. 실행 시 생성하거나 미검수 원고를 보내면 예약 시간에 검수하므로 API 응답에 따른 추가 지연이 있습니다. 생성 후 검수 API 재시도에서도 검수를 생략하지 않습니다.
- **로컬 저장:** 수동으로 로컬 임시저장하는 기능은 미검수 글도 보관합니다. AI로 생성한 예약 원고는 로컬 저장 작업이어도 작성 후 검수를 거칩니다.

AI의 판단은 정확성을 보장하는 외부 사실 확인이 아닙니다. 실제 모델의 내용 교정 품질은 사용자가 원고와 참고자료로 확인해야 하며, 이 버전의 자동 테스트는 모의 API 응답으로 호출 순서·교정 적용·실패 차단·원고 보존을 검증합니다.

## 폴더의 이미지를 원고에 첨부하기

1. **폴더에서 선택**을 누르고 `바탕화면 → test1`처럼 본인이 사용할 폴더를 선택합니다.
2. 폴더의 이미지 목록에서 `1.png`를 찾습니다. 파일명·하위 폴더 검색을 사용할 수 있습니다.
3. 사용할 파일의 체크박스를 선택하고 **선택한 이미지 첨부**를 누릅니다. **이미지 파일 선택**으로 파일을 직접 고를 수도 있습니다.
4. 썸네일을 확인하고 **앞으로/뒤로**로 첨부 순서를 바꾸거나 **제거**로 빼세요. 위치를 지정하지 않은 사진은 본문과 해시태그 뒤에 첨부 순서대로 전달됩니다. 위치가 지정된 사진은 본문의 삽입 표시 순서를 따릅니다.
5. 원고를 저장하거나 예약합니다. 첨부 시 원본 파일을 확장 프로그램의 IndexedDB에 복사하며, 예약은 이미지 식별자를 함께 보관합니다. 원본을 이동·변경·삭제해도 이미 첨부한 이미지의 저장본은 유지됩니다. 수정된 원본을 쓰려면 다시 선택해야 합니다.
6. 네이버 실행 시 사진 파일 입력란에 실제 파일을 전달하고 선택한 장수의 새 이미지가 업로드 완료 상태인지 확인합니다. 입력란·업로드 완료를 확인하지 못하면 사진 없이 발행하지 않고 **화면 확인 필요**로 멈춥니다. 실제 SmartEditor 사진 업로드는 로그인 환경에서 별도 검증이 필요합니다.

지원 파일은 PNG/JPG/GIF/WebP이며 **장당 10MB, 원고당 10장·합계 40MB, 이미지당 6천만 화소 이하**입니다. 파일 헤더와 이미지 디코딩으로 확인하며 SVG·확장자만 바꾼 파일은 받지 않습니다. 폴더 목록은 이름 기준으로 후보를 표시하며 실제 검증은 첨부할 때 수행합니다.

파일 경로를 문자열로 입력하는 것만으로 다른 폴더를 읽을 수 없습니다. 폴더 선택창에서 사용자가 허용한 파일만 읽습니다. 전체 바탕화면 경로 대신 선택 폴더 기준 상대 경로를 표시합니다. 폴더 전체를 자동으로 첨부하거나 감시하는 기능은 없습니다. 이미지 파일은 AI 생성 API에 전송하지 않으며, 네이버 작업을 실행할 때 네이버 편집기에 전달합니다.

로컬 저장·미리보기·예약·원고 불러오기에서 이미지와 삽입 위치를 함께 유지합니다. **원고 복사**는 삽입 표시를 포함한 텍스트만 복사합니다. **미사용 이미지 정리**는 현재 원고·임시저장·작업 기록에서 참조하지 않고 추가 후 10분이 지난 파일만 지웁니다. 확장 프로그램을 삭제하거나 저장소를 지우면 이미지 저장본도 사라질 수 있습니다.

## 본문 중간에 이미지 삽입하기

예를 들어 `FI.png`를 A와 B 사이에 넣으려면 다음과 같이 설정합니다.

1. FI.png를 첨부합니다.
2. 이미지 카드의 **삽입 표시**에 `1`을 입력합니다. `FI`처럼 한글·영문·숫자·밑줄·하이픈으로 된 이름도 사용할 수 있습니다.
3. 본문을 `A[[1]]BCDE`로 작성합니다. 보통 문단 사이의 독립된 줄에 `[[1]]`을 넣으면 관리하기 쉽습니다.
4. **미리보기**를 누르면 `A → FI.png 이미지 → BCDE` 순서로 보입니다.
5. 실행 시 `[[1]]`을 지운 위치에 사진을 업로드하고, 제목·텍스트·이미지가 계획한 순서대로 들어갔는지 대조한 뒤 저장·발행합니다. 사진이 끝으로 잘못 들어가면 완료로 처리하지 않고 멈춥니다.

본문 원하는 위치에 커서를 두고 이미지 카드의 **커서 위치에 삽입**을 눌러도 됩니다. 표시가 없으면 번호를 자동 지정하며, 기존 표시가 있으면 중복 추가하지 않고 그 위치를 옮깁니다. 표시 이름을 바꾸면 본문의 기존 표시도 바뀌고, 이미지 제거·표시 해제 시 연결된 표시를 본문에서 지웁니다.

일반 숫자 `1`은 치환하지 않습니다. `[[1]]`처럼 이중 대괄호로 된 삽입 표시만 사용합니다. 한 표시는 이미지 하나에 연결하고 본문에서 한 번만 사용합니다. 연결 없는 표시, 표시 없는 연결, 중복 표시는 미리보기·예약·실행에서 오류로 안내합니다. 작성 중 임시저장은 미완성 위치 설정도 보관할 수 있습니다.

표시 없는 이미지는 기존처럼 본문 끝에 첨부됩니다. 미리보기 드래그로 이동하는 기능은 포함하지 않으며, 본문 커서 삽입과 표시 이동으로 위치를 바꿉니다. 실제 로그인된 네이버에서의 중간 사진 배치 성공은 별도 검증이 필요합니다.

## 네 가지 실행 방식

| 작업 | 동작 |
|---|---|
| 로컬 임시저장 | 이 Chrome 확장 프로그램에 원고 저장. 네이버에 전송하지 않음 |
| 네이버 편집기 채우기 | 로그인된 Chrome에서 새 글을 열고 제목·본문 입력. 저장/발행 버튼은 누르지 않음 |
| 네이버 임시저장 | 입력 후 저장 버튼을 누르고 새 저장 완료 안내 확인. 확인이 안 되면 화면 확인 필요로 남김 |
| 네이버 발행 | 입력 후 발행 설정·최종 발행 버튼을 누르고 해당 블로그의 새 게시글 주소 확인 |

블로그 ID는 `https://blog.naver.com/본인ID`의 마지막 값입니다. 네이버 로그인은 크롬에서 직접 하며 비밀번호를 확장 프로그램에 저장하지 않습니다. 네이버 작업은 작업 탭을 열어 눈으로 확인할 수 있습니다.

**먼저 편집기 채우기로 실제 블로그의 입력을 확인하세요.** SmartEditor DOM 구조가 다르거나 작성 중 글 복구·보안문자가 나오면 자동 처리하지 않고 작업 탭을 남깁니다. 기존 본문·사진이 있는 글을 덮어쓰지 않습니다. 공개 범위와 카테고리는 네이버 편집기 기본 설정을 따르며 확장 프로그램에서 자동 지정하지 않습니다.

## 예약과 자동 임시저장

- 예약은 **날짜·시·분·초 지정** 또는 **지금부터 시·분·초 후**를 지원합니다. 날짜 입력의 시간대는 화면에 표시한 PC 시간대입니다.
- 네이버 자체 서버 예약발행 기능과 다릅니다. 예약 시각에 확장 프로그램이 작업을 실행합니다.
- 초 단위로 지정할 수 있지만 정확한 초에 발행이 보장되지는 않습니다. Chrome 알람·기기 절전·로딩·API 생성에 지연이 있습니다. 대시보드를 열어두면 1초마다 예약을 확인합니다.
- Chrome이 종료됐거나 기기가 꺼져 있으면 실행하지 못합니다. 다시 켜면 밀린 대기 작업을 순서대로 실행할 수 있으므로 필요 시 **전체 일시정지**를 사용하세요. 일시정지는 다음 작업부터 적용되며 실행 중 작업은 따로 취소합니다.
- 예약은 등록 당시 원고의 복사본입니다. 현재 원고를 나중에 수정해도 기존 예약은 변하지 않습니다. 변경하려면 해당 예약을 취소하고 새로 등록합니다.
- 제목·본문을 비워 예약하면 실행 시 API로 생성합니다. 발행 시간의 지연을 줄이려면 미리 생성·검토한 원고를 예약하세요.
- 원고의 **자동 임시저장**은 시·분·초 주기로 현재 원고 한 개를 복원용으로 저장합니다. 대시보드가 열려 있을 때 동작하며 최소 1초입니다. 0시 0분 0초도 1초로 처리합니다.
- **로컬 임시저장 버튼**과 예약의 로컬 저장은 별도 원고 목록에 최대 200개 보관합니다. 오래된 것부터 제거되므로 JSON 백업을 권장합니다.

## 실패·중단·중복 처리

- API 연결/429/서버 오류는 편집기를 열기 전 최대 2회 재시도합니다. 인증·형식 오류는 자동 재시도하지 않습니다. 응답 유실 시 생성 API가 다시 호출되어 추가 비용이 생길 수 있습니다.
- 편집기를 연 후 오류가 나면 **화면 확인 필요**입니다. 이미 발행됐을 수 있어 자동으로 다시 보내지 않습니다.
- 실행 중 확장 프로그램이 재시작돼도 같은 글을 다시 보내지 않고 화면 확인 필요로 남깁니다.
- 취소는 아직 실행하지 않은 단계부터 멈춥니다. 이미 누른 저장·발행을 취소하거나 글을 삭제하지 않습니다.
- 같은 블로그·내용·작업의 기록이 있으면 중복 등록을 막습니다. 이 확장 프로그램의 작업 기록 기준이며 네이버 전체 기존 글과 대조하는 기능은 아닙니다. 종료 기록 정리 후에는 해당 중복 방지 이력도 없어집니다.
- 확인 필요 작업은 작업 탭을 확인하고 수동 완료 처리합니다. 기존 원고를 다시 보낼 때는 실제 게시 여부를 먼저 확인하세요.

## 로그·백업

- 상세 로그/결과만, 수준·검색 필터, CSV 내보내기를 제공합니다. 최근 3,000건의 시각·단계·작업 ID·오류·예약 대비 지연을 저장합니다.
- 화면의 JSON 백업에는 현재 원고·임시저장·작업 결과와 첨부 이미지 파일을 넣고 API 키를 제외합니다. 이미지 원본 합계 100MB, 가져올 JSON 파일 160MB까지 지원합니다. 이미지 해시·크기·형식을 확인한 뒤 가져오며, 현재 원고와 작업 원고도 로컬 임시저장으로 복원합니다. 기존 예약을 자동 실행하지 않습니다. 이미지 파일이 들어 있지 않은 이전 백업은 같은 기기에 저장본이 있거나 이미지를 다시 선택해야 복원할 수 있습니다.
- 작업은 최대 500개입니다. 종료 기록 정리로 여유 공간을 확보합니다. 이 기기의 확장 프로그램을 삭제하면 로컬 데이터도 사라질 수 있습니다.

## 검증 범위와 개발 확인

공급자 API는 mock 응답으로 요청 형식·모델 조회·오류 처리를 테스트합니다. 실제 유료 API 호출 및 로그인된 네이버에서의 실발행 성공은 API 키/로그인 환경에서 별도 확인이 필요합니다. 에디터 구조가 맞지 않으면 완료로 위장하지 않고 멈춥니다.

저장소 루트에서 `node --test test/blog-publisher.test.js`로 핵심 테스트를 실행합니다. 브라우저 통합 점검은 `node scripts/check-blog-publisher-browser.mjs`입니다. 브라우저 점검은 별도 임시 프로필에서 실행하며 사용자의 네이버 계정에 로그인하거나 실제 게시하지 않습니다.
